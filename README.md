# Kavi — Offline Speech-to-Speech Translation (Prototype)

Kavi is a fully **offline, on-device** speech-to-speech translation system for **Vietnamese ↔ English** (Chinese/Korean planned), built for the **OneVoice AI Challenge** (Saigon AI Hub × Qualcomm, May–Nov 2026) and targeting a Snapdragon 8 Gen 2 Android phone.

This repository is the **host-side track** — the benchmark harness and the published results — and a submodule of [`aivoice-2026`](https://github.com/TanKhoiTV/aivoice-2026), which hosts the public program docs and CI. The third-party model weights are fetched on demand with `make models` rather than committed (see [`NOTICE`](NOTICE)).

> The on-device track — the Android application, its ADR register and the QAIRT conversion toolchain — lives in a separate private repository (`kavi-android`) and is not publicly available.

## Repository layout

| Path | Purpose |
| ------ | --------- |
| `models/` | CTranslate2 Opus-MT VI→EN weights + SentencePiece tokenizers (fetch with `make models`; not committed). |
| `scripts/` | Asset fetchers/verifiers (`make models` / `make data` / `make verify-assets`) + the public-boundary check. |
| `assets.lock.toml` | Pinned third-party asset revisions + SHA-256 digests. |
| `voices/` | Piper TTS voice models (e.g. `en_US-lessac-medium`). |
| `bench/` | Benchmark harness: candidate adapters, scorer, eval-manifest schema, data prep. |
| `docs/benchmark/` | Published v1 results, the Typst report and its charts. |
| `docs/reference/` | Measurement pages: corpus catalog, denoising gate, beam-sweep aggregate, VAD pause distribution, endpointing gate, competitive/literature context, UX review corpus, training feasibility, AI Hub capability, Phase-3 requirements. Index in `docs/reference/README.md`. |
| `docs/decisions/` | The public register: ADR-032 (MT model choice) and the open parameters measured here. |
| `.kavi.yaml` | The published gates and claims — the public half of the split configuration. |
| `eval_data/` | Generated eval audio / downloaded corpora used by the harness. |
| `bench-results/` | Benchmark run outputs (gitignored). |

## Quickstart

```bash
make setup         # deps + pinned model weights + FLEURS data + eval manifest
make check         # lint + format check
make test          # pytest
```

`make setup` needs network access and ~1.5 GB of downloads; `make setup-min` is the offline path (fallback eval set). See [`CONTRIBUTING.md`](CONTRIBUTING.md) for prerequisites, the Windows notes, and the individual `make models` / `make data` / `make verify-assets` steps.

## Benchmark harness (v0)

The `bench/` package is a pluggable, off-device benchmark harness for the ASR → MT → TTS candidate stack. It runs today on CPU-default, license-clean candidates:

```bash
make models       # fetch pinned Opus-MT weights/tokenizers (~289 MB, one-time)
make data         # fetch pinned FLEURS vi_vn/en_us test parquets (~1.1 GB, resumable)
make bench-data   # build the lean eval set -> eval_data/eval_manifest_v1.json
make bench        # run the harness (offline smoke: Opus-MT vi->en + Piper EN TTS)
make verify-assets  # check downloaded digests against assets.lock.toml
```

ASR items use real VI/EN speech from FLEURS parquets. Real-noise clips (MUSAN/RIRS_NOISES) can be swapped in via `build_lean_manifest(real_noise_dir=...)`. See `docs/reference/benchmarking-plan.md` and `docs/reference/benchmarking-todo.md`.

> Public program documentation (contest info, specifications, onboarding) lives in the parent repo `aivoice-2026/docs/`.

## Status

Host-side track, actively measured. The prior implementation is archived in `aivoice-2026/archive/`; the v0 benchmark harness lives in `bench/`; application source is in the private `kavi-android` repository.

The on-device turnaround gate is **met and measured** — 1849.4 ms median, 10/10 runs inside the 2.0 s budget, peak RSS 589 MB on the target phone. That figure is MT-to-first-audio measured plus 500 ms VAD and 83 ms ASR added arithmetically; a single end-to-end run of the whole chain is the open measurement and the first item in [`HANDOFF.md`](HANDOFF.md).

Phase-3 prototype submission is due **13/11/2026, 23:59**. Requirements and gaps: [`docs/reference/phase3-submission-requirements.md`](docs/reference/phase3-submission-requirements.md).

What is settled, what was retracted, and what to do next are in [`HANDOFF.md`](HANDOFF.md).
